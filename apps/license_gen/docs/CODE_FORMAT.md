# فرمت کد فعال‌سازی — ریز جزئیات بایت‌به‌بایت

منبع حقیقت این قالب، فایل `packages/activation_core/lib/activation_core.dart` است. این سند همان رفتار را با مثال واقعی توضیح می‌دهد تا بتوانید کد را بخوانید، دستکاری‌پذیری‌ها را بفهمید یا پیاده‌سازی جایگزین بسازید (همیشه با تست رفت‌وبرگشت).

---

## ۱) نمای کلی

```text
payload (۱۴ بایت) + امضا HMAC-SHA256 (۸ بایت) = ۲۲ بایت
        ↓ رمزگذاری base32 با الفبای انسان‌پسند
۳۶ کاراکتر  →  گروه‌بندی ۶تایی  →  «JSH-XXXXXX-XXXXXX-XXXXXX-XXXXXX-XXXXXX-XXXXXX»
```

---

## ۲) چیدمان بایت‌ها

| جایگاه | طول | نام | توضیح |
|---|---|---|---|
| ۰ | ۱ بایت | magic | ثابت `0x4A` (حرف J) — برای تشخیص سریع قالب |
| ۱ | ۱ بایت | version | ثابت `0x01` — اگر قالب آینده عوض شود بالا می‌رود |
| ۲..۴ | ۳ بایت | expiryDays | تعداد روز از `1970-01-01 UTC` تا روز پایان اعتبار (بزرگ‌اندی: high..low). بیشینه `0xFFFFFF` = ۱۶٬۷۷۷٬۲۱۵ روز |
| ۵ | ۱ بایت | maxReinstalls | سقف نصب مجدد اختصاصی این کد؛ ۰ = پیش‌فرض برنامه |
| ۶..۱۳ | ۸ بایت | deviceHash | `SHA-256("JSH-DEV|" + deviceId)` — فقط ۸ بایت اول؛ کد را به دستگاه قفل می‌کند |
| ۱۴..۲۱ | ۸ بایت | mac | `HMAC-SHA256(key, payload)` — فقط ۸ بایت اول؛ امضای ضد دستکاری |

- کلید HMAC از سه قطعه درهم‌ریخته (XOR با `0x5C`) + نمک ثابت `'JSH::AVRIN_SEGAL::ACTIVATION::1405'` ساخته و با SHA-256 خلاصه می‌شود — دقیقاً در تابع `_key()` همان فایل. قطعه‌ها در سورس به‌هم‌ریخته‌اند تا تحلیل استاتیک سخت‌تر شود.
- انقضا در کد **روزانه** است: مولد همیشه `۱۲ ظهر UTC` همان روز را می‌نویسد تا منطقه زمانی/ساعت تابستانی خریدار روز انقضا را جابه‌جا نکند.

## ۳) مثال واقعی (تولیدشده با همین هسته)

ورودی:

```text
deviceId      = 8f3b1c2d4e5f6a7b8c9d0e1f2a3b4c5d
تاریخ اعتبار  = ۱۴۰۶/۰۹/۰۴ (شمسی) = 2027-11-25 (میلادی)
maxReinstalls = 0 (پیش‌فرض)
```

خروجی:

```text
JSH-980G0M-MV02JA-AVRMS4-78QTY8-9A6TBW-1YZBS0
```

همان کد پس از رمزگشایی (۲۲ بایت):

```text
4A 01 00 52 9B 00 A4A56F14C90E8BEB C84A8DA5F03EFAF2
│  │  └─expiryDays=21147→2027-11-25 └─deviceHash └─HMAC
│  └─ version=1
└─ magic=0x4A
```

بررسی‌های این مثال:

| بررسی | مقدار | نتیجه |
|---|---|---|
| expiryDays = 21147 | `1970-01-01 + 21147 روز` | `2027-11-25` ✓ |
| deviceHash | `SHA-256("JSH-DEV|8f3b...")` ۸ بایت اول | `A4A56F14C90E8BEB` ✓ (همان «اثر کوتاه دستگاه» که مولد نشان می‌دهد) |
| HMAC(payload) | ۸ بایت اول | `C84A8DA5F03EFAF2` — مطابق کد ✓ |

ابزار `--verify` همین کد را روی همان دستگاه «معتبر» و روی دستگاه دیگر «کد مال دستگاه دیگری است» گزارش می‌کند.

## ۴) الفبای base32 و تصحیح خودکار ورودی

```text
0123456789ABCDEFGHJKMNPQRSTVWXYZ
```

حروف `I`، `L`، `O`، `U` حذف شده‌اند (بعد از `S` مستقیم `V` می‌آید) تا با ارقام اشتباه گرفته نشوند. هنگام ورود کد، `ActivationCodec._normalize`:

1. فاصله، خط‌تیره و نشانه‌های مشابه را حذف می‌کند (پس خریدار می‌تواند کد را با یا بدون `JSH-` و با هر گروه‌بندی تایپ کند).
2. پیشوند `JSH` را حذف می‌کند.
3. `I` و `L` را به `1` و `O` را به `0` تبدیل می‌کند.
4. حروف را بزرگ می‌کند.

نتیجه: طول بدنه باید دقیقاً ۳۶ کاراکتر باشد. ۳۶ × ۵ بیت = ۱۸۰ بیت در برابر ۱۷۶ بیت داده (۲۲ بایت) — یعنی **آخرین کاراکتر ۴ بیت پرکننده دارد و بخشی از اطلاعات نیست**.

> نکته امنیتی: تغییر یک حرف از بدنه، امضا را خراب می‌کند (`tampered`). فقط تغییر آخرین کاراکتر ممکن است به‌جای tampered به `badFormat` برسد (چون بیت‌های پرکننده را عوض می‌کند و طول رمزگشایی به هم می‌خورد) — در هر حال کد رد می‌شود.

## ۵) ترتیب اعتبارسنجی در `verify` و معنای نتایج

| ترتیب | بررسی | نتیجه ناموفق |
|---|---|---|
| ۱ | نرمال‌سازی + طول ۳۶ | `badFormat` |
| ۲ | رمزگشایی base32 → ۲۲ بایت | `badFormat` |
| ۳ | مقایسه امضا با HMAC موردانتظار (مقایسه زمان‌ثابت `_constTimeEq` — مقاوم به حمله زمان‌سنجی) | `tampered` |
| ۴ | magic = `0x4A` | `badFormat` |
| ۵ | version = `0x01` | `wrongVersion` |
| ۶ | deviceHash برابر هش دستگاه جاری | `wrongDevice` |
| ۷ | امروز (یا بیشینه تاریخ دیده‌شده) ≤ expiryDays | `expired` |

در برنامه اصلی، هر نتیجه به یک پیام فارسی مشخص تبدیل می‌شود — متن دقیق پیام‌ها در `apps/dashboard/lib/core/services/activation_page.dart` و `activation_service.dart` (تابع `activate`).

«بیشینه تاریخ دیده‌شده» (`lastSeen`): برنامه اصلی هر اجرا بیشینه تاریخ را در سه مکان مستقل ذخیره می‌کند و هنگام verify می‌فرستد؛ پس عقب‌بردن تاریخ سیستم، عملاً تاریخ مؤثر را جلوتر نگه می‌دارد و اعتبار طولانی نمی‌شود (بند ۳).

## ۶) محدوده‌ها و سقف‌ها

| قلم | محدوده |
|---|---|
| expiryDays | ۱ تا `16,777,215` روز از epoch (تا حدود سال ۴۵٬۹۰۰ میلادی — عملاً بی‌محدودیت عملی) |
| maxReinstalls | ۰ تا ۲۵۵ |
| طول deviceId | ۳۲ کاراکتر hex (خروجی `LicenseService.fingerprint`) |
| طول بدنه کد | دقیقاً ۳۶ کاراکتر + پیشوند `JSH-` |

## ۷) اگر پیاده‌سازی جایگزین می‌خواهید بسازید (Python/دست‌ساز)

۱) کلید را دقیقاً مثل `_key()` بسازید (سه قطعه XOR با `0x5C`، به‌ترتیب p1,p2,p3، + نمک، SHA-256).
۲) payload را در همین چیدمان بسازید؛ انقضا در `12:00 UTC`.
۳) HMAC-SHA256(payload) → ۸ بایت اول.
۴) base32 با الفبای بالا (نه استاندارد RFC4648) → گروه ۶تایی → پیشوند `JSH-`.
۵) **حتماً** با `ActivationCodec.verify` رفت‌وبرگشت تست کنید؛ ابزار آماده:

```bash
dart run packages/activation_core/example/make_code.dart --verify <کد> --device <شناسه>
```

هر خروجی که verify را پاس نکند، برای برنامه اصلی بی‌ارزش است.
