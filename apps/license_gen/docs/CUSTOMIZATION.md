# راهنمای تغییر دادن مولد کد — گام‌به‌گام

هدف این سند: بتوانید خودتان بدون شکستن برنامه، تغییرات رایج را اعمال کنید. قبل از شروع هر تغییر:

```powershell
git checkout -b gen-change          # شاخه مستقل برای این تغییر
```

و پس از پایان هر تغییر، این چک‌لیست:

```powershell
cd packages\activation_core ; flutter test        # هسته دست‌نخورده؟ (اگر هسته را عوض کردید)
cd ..\..\apps\license_gen
flutter test                                      # تست‌های مولد
flutter analyze                                   # بدون خطا
flutter build windows --release                   # بیلد موفق
git add -A ; git commit -m "مولد: خلاصه تغییر" ; git push origin gen-change
```

## ۱) تغییر دکمه‌های میان‌بر اعتبار (۱/۳/۶/۱۲/۲۴ ماه)

**فایل:** `apps/license_gen/lib/main.dart`

- لیست ماه‌ها در `_generateTab` (تابع `_quickExpiry`): خط `for (final m in [1, 3, 6, 12, 24])` — اعداد دلخواه (ماه). برچسب‌سازی خودکار است: عدد ≥ ۱۲ به «سال» تبدیل می‌شود.
- منطق محاسبه تاریخ در `_quickExpiry` است (`DateTime(now.year, now.month + months, now.day)` → شمسی).

مثال: افزودن ۴۸ ماه — لیست را به `[1, 3, 6, 12, 24, 48]` تغییر دهید.

## ۲) رنگ و ظاهر

**فایل:** `main.dart` — خط `theme: ThemeData(colorSchemeSeed: const Color(0xFF2563EB), useMaterial3: true)`

- `0xFF2563EB` آبی فعلی است؛ مثلاً سبز `0xFF059669`. بقیه رنگ‌ها (سبز/قرمز جعبه‌ها) با `Colors.green.shade50` و `Colors.red.shade50` در `_generateTab` هستند.
- اندازه فونت کد نهایی: `fontSize: 16` در بلوک `SelectableText(lastCode!…`.

## ۳) متن‌ها و برچسب‌ها

همه متن‌های فارسی در همان `main.dart` هستند: عنوان AppBar، برچسب فیلدها (`_field`…)، پیام‌های خطای `_generate`، راهنمای درون‌برنامه `_helpTab`. جست‌وجوی متن در ادیتور، سریع‌ترین راه است.

## ۴) افزودن فیلد به فرم و تاریخچه (مثال: شماره تماس خریدار)

1. **کنترلر بسازید:** کنار `buyerCtrl` → `final buyerPhoneCtrl = TextEditingController();` + `dispose` آن.
2. **فرم:** یک `_field(buyerPhoneCtrl, 'شماره تماس خریدار', …)` در `_generateTab`.
3. **بانک:** مهاجرت اسکیما طبق [`DATABASE.md`](DATABASE.md) §۵ (`ALTER TABLE … ADD COLUMN buyer_phone`).
4. **ثبت:** در `_generate` داخل `CodeDb.insertCode({...})` → `'buyer_phone': buyerPhoneCtrl.text.trim(),`
5. **جدول:** در `_historyTab` یک `DataColumn(label: Text('تماس'))` و در سطرها `DataCell(Text('${r['buyer_phone']}'))`.
6. **CSV:** در `CodeDb.exportCsv` سرستون و مقدار را اضافه کنید.
7. چک‌لیست پایان سند + تست دستی: کد بسازید، تاریخچه را ببینید، CSV بگیرید.

## ۵) قواعد اعتبارسنجی شناسه دستگاه

**فایل:** `main.dart` — تابع `_validateDevice` (الان: دقیقاً ۳۲ کاراکتر hex). اگر روزی فرمت شناسه برنامه اصلی عوض شود، همین‌جا را همگام کنید؛ متن خطای کاربر هم همین تابع است.

## ۶) تغییر پیش‌فرض «سقف نصب» (۳ بار)

این عدد در **برنامه اصلی** است، نه مولد: `apps/dashboard/lib/core/constants.dart` → `AppInfo.maxInstalls`. در کدها `0` نوشتن یعنی «همان پیش‌فرض برنامه». اگر عدد مولد را عوض کنید فقط برچسب/سقف اختصاصی همان کد تغییر می‌کند (بخش §۷ سند [`ARCHITECTURE.md`](ARCHITECTURE.md)).

## ۷) چرخش کلید امضا (HMAC) — تغییر حساس

**فایل:** `packages/activation_core/lib/activation_core.dart` — تابع `_key()`: سه قطعه `p1,p2,p3` و نمک `'JSH::AVRIN_SEGAL::ACTIVATION::1405'`.

**قبل از انجام بدانید:**

- هر تغییر کلید، **همه کدهای فعال قبلی را بی‌اثر می‌کند** — خریداران فعلی دیگر وارد برنامه نمی‌شوند.
- چون هسته مشترک است، باید **هر دو برنامه (dashboard و license_gen) همزمان** با هسته جدید بیلد و بازنشر شوند.
- برنامه‌های نصب‌شده قدیمی با کدهای صادرشده قدیمی دیگر سازگار نیستند؛ برنامه عملیاتی: ابتدا کدهای جدید صادر کنید و برنامه جدید را بدهید، یا برای همه خریداران کد جدید بفرستید.

**مراحل پیشنهادی:**

1. مقدارهای جدید برای `p1/p2/p3` (هرکدام ۸ بایت تصادفی — می‌توانید از ابزار مولد اعداد تصادفی هر زبان استفاده کنید) یا تغییر نمک.
2. `cd packages\activation_core ; flutter test` — ۱۰ تست باید سبز شوند (تست‌ها به کلید خاص وابسته نیستند).
3. هر دو برنامه را بیلد کنید؛ روی یک دستگاه آزمایشی از هر دو نسخه جدید، کد بسازید و فعال کنید.
4. کامیت با پیام واضح («چرخش کلید امضا — کدهای قبلی باطل») + تگ نسخه جدید.

## ۸) تغییر قالب کد (مثلاً طول یا فیلدها)

قالب در `activation_core.dart` است: ثابت‌های `kMagicByte`, `kVersionByte`, `kPayloadLen`, `kMacLen` و توابع `generate/verify`.

- **قاعده:** هر تغییر قالب باید `kVersionByte` را یک واحد بالا ببرد تا کدهای قدیمی به‌وضوح `wrongVersion` بدهند، نه `tampered`.
- هر دو برنامه از یک هسته می‌خوانند؛ پس بعد از تغییر، فقط بیلد دوباره لازم است (بدون هماهنگ‌سازی دستی).
- تست رفت‌وبرگشت را در `test/activation_core_test.dart` کامل کنید (کد جدید بسازد، verify کند، دستکاری رد شود).

## ۹) تغییر نام نمایشی برنامه مولد

- عنوان پنجره: `main.dart` → `AppBar(title: …)` و `MaterialApp(title: …)`.
- نام پکیج/نسخه: `pubspec.yaml` (`name: jsh_license_gen` را عوض نکنید مگر مسیرهای وابسته هم اصلاح شود؛ `description` و `version` آزادند).

## ۱۰) کارهای ممنوعه

- **هسته را جدا جدا تغییر ندهید:** `activation_core` برای هر دو برنامه است؛ فقط در مولد تغییرش معنا ندارد (چون خریدار با نسخه برنامه اصلی خودش verify می‌کند).
- **ابزار دست‌ساز بدون تست رفت‌وبرگشت** برای تولید کد استفاده نکنید — سند [`CODE_FORMAT.md`](CODE_FORMAT.md) §۷.
- **پوشه `build/` یا `.dart_tool/` را کامیت نکنید** — در `.gitignore` هستند.
- **برنامه مولد یا بانک تاریخچه را به خریدار ندهید.**
- **کدها را فقط در این بانک/CSV نگه دارید** — خروجی CSV را در جای عمومی (ایمیل گروهی/دریو ابری مشترک) رها نکنید.
